# Hero Card and Scroll Motion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Build the approved top of the bento page and scroll-driven motion.
The top has the intro card, the "Portfolio" wordmark, the video placeholder,
the counted number tiles and a desktop side menu.

**Architecture:**
- The new tiles live in `components/bento/hero.tsx` and slot into the
  existing grid. On desktop they use explicit `lg:` placement; on phones
  they keep DOM order.
- Scroll reveal is a client-only `data-reveal` state on `Tile`, so server
  HTML is always visible.
- Parallax uses Motion's `useScroll`.

**Tech Stack:** Next.js 16, React 19, Tailwind 4, motion 14 and vitest,
all already in the repo.

**Spec:** `docs/superpowers/specs/2026-11-27-hero-card-design.md`

## Global Constraints

- **Numbers are computed, never typed in:**
  - `projectCount() === projects.length`, which is 4
  - `toolCount()` is the number of unique ids in `skills`, which is 24
- **Colours:** only the palette tokens, plus the PeraFlow and Lynko logo
  files.
- **Reduced motion:** no loops, parallax, count-up or reveal. Everything is
  shown immediately.
- **Server HTML:** every tile is visible. Only tiles that are off screen
  after mount may be hidden, waiting to reveal.
- **The page keeps exactly one `h1`.**

## Review Focus

1. **No `IntersectionObserver`** (old browsers, jsdom): nothing stays hidden.
2. **Reloading while scrolled halfway down:** tiles above the viewport are
   shown, not stuck hidden.
3. **Filtering while scrolled down:** the grid scrolls into view, and dimmed
   tiles stay dimmed after they reveal.
4. **320 px:** the intro card text and the badge don't overlap, and the
   "Portfolio" wordmark doesn't overflow.
5. **Video tile:** clicking twice or using the keyboard (Enter/Space) shows
   the message and doesn't throw.

- Test: `tests/bento-grid.test.tsx`, `tests/side-filters.test.tsx`

**Interfaces:**
- `Tile` gains a `place?: string` prop, which carries the `lg:` placement
  classes.
- `useReveal(ref)` sets `data-reveal="pending"` on a tile when all of these
  hold:
  - `IntersectionObserver` exists
  - motion is allowed
  - the tile is below the viewport
  
  It sets `data-reveal="in"` when the tile becomes visible.
- `SideFilters()` is a vertical `role="group"` with `aria-label="Filter tiles"`,
  hidden below `lg`.
- `revealGrid()` scrolls `[aria-label=Portfolio]` into view when its top is
  above the viewport.
